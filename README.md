# 西北非遗 · 五省手艺影像志

> 聚焦陕西、甘肃、宁夏、青海、新疆五省（区）非物质文化遗产的单页影像志。
> 以真实照片与现场影像为载体，按省份 / 城市 / 门类 / 保护级别组织内容，配有内嵌分布地图与 AI 问答助手。

**提交材料**：技术文档 [`提交材料/技术文档.pdf`](./提交材料/技术文档.pdf) ｜ 演示脚本 [`提交材料/演示视频脚本.md`](./提交材料/演示视频脚本.md) ｜ 提交自查 [`提交材料/提交检查清单.md`](./提交材料/提交检查清单.md)

## 一、项目介绍

### 1.1 要做的事

西北五省（区）拥有逾 300 项国家级非物质文化遗产代表性项目、逾 3000 项省级项目。但这些内容长期散落在政府公告、方志与新闻报道中：**格式不统一、没有图、更没有影像**。普通人想了解「安塞腰鼓到底是什么样」，往往只能搜到一段文字加一张不相干的配图。

本项目把这件事重做了一遍：**为每一项非遗配一张真实照片、一段现场影像、一篇 500 字以上的结构化正文**，并让它们可以在一个页面里被筛、被搜、被问。

### 1.2 项目定位

**不是全量名录，而是代表性项目精选导览。**

- 收录 **67 项**，覆盖五省（区）**34 座城市**、**全部十大门类**
- 每项含四节正文：历史由来 / 技艺特点 / 传承现状 / 冷知识；正文合计 **37,667 字**，平均 562 字/项
- 配 **67 张**实拍照片、**10 段**现场影像
- 页面内明确标注收录口径与官方项目总数，不回避「不全」这件事

### 1.3 数据规模

| 省（区） | 国家级项目（官方口径） | 本站收录 | 覆盖城市 |
|---|---|---|---|
| 陕西省 | 91 项 | 26 项 | 10 座 |
| 甘肃省 | 83 项 | 11 项 | 8 座 |
| 宁夏回族自治区 | 28 项 | 7 项 | 4 座 |
| 青海省 | 约 70~90 项 | 9 项 | 4 座 |
| 新疆维吾尔自治区 | 约 70~90 项 | 14 项 | 8 座 |
| **合计** | **逾 300 项** | **67 项** | **34 座** |

> 官方数字据各省（区）文旅部门 2025 年公开口径；完整名录以中国非物质文化遗产网公布为准。

### 1.4 功能一览

| 模块 | 说明 |
|---|---|
| 首页 | 五省（区）主视觉自动轮播，版块：五省 / 精选 / 影像 / AI / 门类 |
| 五省非遗 | 按省份、城市、门类、关键词多维筛选，支持四种排序 |
| 详情页 | 历史由来、技艺特点、传承现状、冷知识四节正文，首尾有上下篇导航 |
| 分布地图 | 内嵌渲染，仅对有收录的城市打点（34 城），按省五色，点击跳转对应城市 |
| AI 问答 | 流式对话，知识范围限定为本站收录项目；访客可绑定自己的 DeepSeek Key |
| 关于 | 非遗定义、十大门类、为什么是西北、收录范围与数据边界 |

## 二、技术架构

### 2.1 总体架构

纯前端单页应用（SPA）+ 轻量 Node 后端，**零构建、零第三方运行时依赖**。

```
┌──────────────────────────────────────────────────────────┐
│                        浏览器                             │
│  index.html ── style.css ── app.js（哈希路由 + 渲染）       │
│       │            │              │                       │
│       │            │              ├─ data.js    数据层      │
│       │            │              ├─ config.js  配置        │
│       │            │              ├─ videos.js  影像清单     │
│       │            │              └─ manifest.js 图片映射   │
│       │            │                                      │
│       │            └─ MapLibre GL JS（本地化）+ 高德栅格瓦片 │
└───────┼───────────────────────────────────────────────────┘
        │ fetch /api/chat（SSE 流式）
        │ fetch /api/verify · /api/health
        ▼
┌──────────────────────────────────────────────────────────┐
│  server.js（Node 内置模块，零依赖，127.0.0.1:4190）         │
│   ├─ 静态托管（支持 HTTP Range，视频可拖动）                 │
│   ├─ /api/chat    代理 DeepSeek，SSE 透传                  │
│   ├─ /api/verify  校验访客自带 Key（不产生 token 消耗）       │
│   └─ /api/health  健康检查                                 │
└──────────────────────────────────────────────────────────┘
                         │ curl 子进程
                         ▼
                   api.deepseek.com
```

### 2.2 模块职责

| 文件 | 职责 |
|---|---|
| `index.html` | 页面骨架、脚本装配、SEO/OG 元信息 |
| `style.css` | 设计系统（暗色沉浸、衬线标题）与全部版式、响应式、无障碍 |
| `data.js` | 数据层：67 项非遗、5 省区、37 城市、门类与级别 |
| `app.js` | 哈希路由、页面渲染、轮播、筛选、地图装配、对话交互 |
| `config.js` | 地图提供方、后端接口地址等运行期配置 |
| `server.js` | 静态托管 + DeepSeek 对话代理 + Key 校验 |
| `assets/map-tiles.js` | 瓦片地图模块（MapLibre 封装） |
| `assets/vendor/maplibre/` | 本地化的 MapLibre GL JS 4.7.1 |
| `assets/img/manifest.js` | 图片映射表 |
| `assets/videos.js` | 影像清单 |

### 2.3 关键设计决策

| 决策 | 理由 |
|---|---|
| 不引入框架与构建工具 | 单页体量下原生 JS 更小更快；评审可直接运行，无 `npm install` 门槛 |
| 哈希路由而非 History API | 静态托管即可工作，刷新不 404，可部署到任意静态空间 |
| 后端零依赖 | 避免依赖链风险，只用 `http/https/fs/path/child_process/url` |
| 地图用 MapLibre + 高德栅格瓦片 | 高德瓦片免 Key 且国内稳定可达；MapLibre 仅作渲染器，不涉及境外地图服务 |
| 影像全部本地化 | 避免外链失效；缺失时自动回退线上播放器 |

### 2.4 AI 方案速览

- **模型**：DeepSeek（`deepseek-chat` / `deepseek-reasoner`），OpenAI 兼容协议
- **集成**：后端代理 + SSE 流式转发，前端逐块渲染
- **上下文**：系统提示词内置站内 67 项清单（名称 / 城市 / 门类 / 概要），抑制跑题与编造
- **三级降级**：AI 在线 → 演示模式（无 Key）→ 离线知识库（后端不可用）
- **Key 策略**：访客自带 Key 优先于服务器 `.env`，只存本机 `localStorage`

> 完整论证见 [`提交材料/技术文档.pdf`](./提交材料/技术文档.pdf) 第 4 章「AI 技术方案」。

## 三、安装运行指南

### 3.1 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | **18.0.0 及以上** | 仅后端需要；只用内置模块，无需 `npm install` |
| 浏览器 | Chrome / Edge / Firefox 最新版 | 需支持 ES2017+ 与 WebGL（地图渲染） |
| 操作系统 | Windows / macOS / Linux | `启动.cmd` 仅 Windows 适用，其他系统用命令行 |

### 3.2 方式一：一键启动（推荐，Windows）

双击项目根目录的 **`启动.cmd`**。脚本会：探测 Node.js → 启动 `server.js`（同时托管站点与 AI 接口）→ 打开 <http://127.0.0.1:4190/>。

### 3.3 方式二：命令行启动

```bash
# 1. 克隆仓库
git clone <仓库地址>
cd <仓库目录>

# 2. 启动（无需 npm install，项目零依赖）
node server.js

# 3. 浏览器打开 http://127.0.0.1:4190/
```

启动成功输出：

```
[西北非遗] backend on http://127.0.0.1:4190
[西北非遗] DeepSeek: LIVE · deepseek-chat      # 或 DEMO（未配置 Key）
```

> **为什么建议用 4190 打开？** `server.js` 同时托管静态页面与 `/api/chat`，同源访问，不存在跨域和后端找不到的问题。

### 3.4 方式三：纯静态预览（不含 AI）

不使用后端时，用任意静态服务器即可浏览全部内容（AI 会自动退化为离线知识库）：

```bash
python -m http.server 8080
# 访问 http://127.0.0.1:8080
```

### 3.5 配置 AI（可选）

**方式 A：配置服务器 Key（站点统一使用）**

```bash
cp .env.example .env      # Windows: copy .env.example .env
# 编辑 .env，填入 DEEPSEEK_API_KEY
node server.js
```

**方式 B：访客自带 Key（无需改文件）**

打开页面 →「AI 问答」→ 点底部「绑定我的 API Key」→ 填入自己的 Key →「校验并保存」。
Key 仅存于本机浏览器 `localStorage`，只发往本机后端代转发。

### 3.6 常见问题

| 现象 | 原因与处理 |
|---|---|
| AI 显示「离线知识库模式」 | 后端未启动。运行 `node server.js`，或双击 `启动.cmd` |
| AI 显示「演示模式」 | 后端已启动但未配置 Key。配置 `.env` 或在页面绑定自己的 Key |
| 地图显示「需要授权」 | 浏览器 WebGL 不可用或瓦片网络不通，检查硬件加速 |
| 视频打不开 | 检查 `assets/video/` 文件完整性；缺失时页面自动回退线上播放器 |
| 端口 4190 被占用 | 修改 `.env` 的 `PORT`，并同步改 `config.js` 的 `CHAT_ENDPOINT` |

## 五、环境配置

### 5.1 环境变量

复制 `.env.example` 为 `.env`（已被 `.gitignore` 排除，**不会进入仓库**）。

| 变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | 否 | 空 | DeepSeek API Key；留空则后端进入演示模式 |
| `DEEPSEEK_MODEL` | 否 | `deepseek-chat` | 默认模型，可选 `deepseek-reasoner` |
| `DEEPSEEK_API_BASE` | 否 | `https://api.deepseek.com` | 接口地址，一般无需修改 |
| `PORT` | 否 | `4190` | 后端监听端口 |
| `CURL_BIN` | 否 | 系统 `curl` | 代理转发所用 curl 路径 |

> ⚠️ **安全说明**：仓库中不包含任何真实 Key。全部密钥通过环境变量或运行时输入，符合大赛「API 密钥等敏感信息不得出现在公开仓库中」的要求。

### 5.2 依赖清单

**Node 端**：无第三方依赖（`dependencies` 与 `devDependencies` 均为空），仅用内置模块：
`http` · `https` · `fs` · `path` · `child_process` · `url`

**浏览器端**：唯一第三方库为 MapLibre GL JS 4.7.1，已本地化至 `assets/vendor/maplibre/`，不依赖 CDN。

**字体**：全部使用系统中文字体（宋体 / 思源宋体 / 苹方 / 微软雅黑），无网络字体请求。

### 5.3 数据与素材约定

> ⚠️ **影像未纳入 Git 仓库**：10 段影像合计 432 MB，其中 `qinqiang.mp4` 单文件 158 MB，超过 GitHub / Gitee 单文件 100 MB 限制，且当前环境无 Git LFS。因此 `.gitignore` 已排除 `assets/video/*.mp4`，影像随作品压缩包提交。
> **从 Git 克隆的仓库依然可以完整演示影像**——本地文件缺失时，播放器自动回退哔哩哔哩在线播放（`bvid` 已保存在 `videos.js`）。恢复方法见 [`assets/video/README.md`](./assets/video/README.md)。

| 目录 | 约定 |
|---|---|
| `assets/img/` | 文件名与 `manifest.js` 的 key 一一对应；新增条目须同时登记 |
| `assets/video/` | 文件名与 `videos.js` 的 `file` 字段对应；缺失时自动回退线上播放器 |
| `data.js` | 新增项目的 `cityId` 必须存在于 `CITIES`，否则地图打点会漏 |
